Познакомиться с функциями библиотеки ubus (libubus)

- Познакомиться со структурой шины ubus
- Научиться регистрировать объекты с функциями на шине
- Научиться пользоваться утилитой ubus (команды monitor, list, call)
- Познакомиться с форматом данных blobmsg и blob (binary large object). https://lxr.openwrt.org/source/libubox/blob.h. Схематично формат blob_attr показан тут https://gtrboy.github.io/posts/bus/
- Узнать, что происходит на шине при регистрации/дерегистрации/вызове (ubus monitor)

Все взаимодействие с шиной происходит путем обмена сообщениями в формате blobmsg/blob через сокет-файл с управляющей службой (демоном) ubusd. Архитектура шины клиент-серверная, ubusd - это посредник между клиентом и сервером.

    Написать утилиту, выполняющую роль сервера. Утилита будет называться tubus. Утилита регистрирует на шине один объект "/test" с одним методом print. Метод print без аргументов. Сам метод print должен ответить blobmsg-сообщением с полями (атрибутами):

 

"message" - строковое поле с содержимым "Hello UBUS!"

"uptime" - 32-битное целочисленное поле, содержащее время работы системы в секундах с момента загрузки ОС


Метод будет всегда возвращать код результата 0 (успех).
Утилита будет запускаться в фоновом режиме "tubus &".
Пример использования:

ubus call /test print
 {
    "message": "Hello UBUS!",
    "uptime": 2010
}

 

Усложнение:

Работа с переменными окружения процесса

Метод print должен распечатать (вернуть) список переменных окружения текущего процесса в формате:

{
"<переменная1>":"<значение1>",
"<переменная2>":"<значение2>",
"<переменная3>":"<значение3>",
...
}

Порядок не имеет значения.

Пример:

{
    "PATH": "/usr/sbin:/usr/bin:/sbin:/bin",
    "ENV":"/etc/shinit",
...
}

Добавить метод set с аргументами name и value. name и value - строковые переменные. Если при чтении аргументов обнаружена ошибка - вернуть код ошибки UBUS_STATUS_INVALID_ARGUMENT. Параметры обязательные, пустые строки недопустимы. Метод должен изменить/создать переменную окружения с указанным именем.

Пример использования метода set:

ubus call /test set '{"name":"MY_VAR","value":"my_value"}'
ubus call /test print
{
    "PATH": "/usr/sbin:/usr/bin:/sbin:/bin",
    "ENV":"/etc/shinit",
    "MY_VAR":"my_value",
    ...
}

Хорошо понимать типы blob и blobmsg, разницу между ними
